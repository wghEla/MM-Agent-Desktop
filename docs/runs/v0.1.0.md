## 自查（Self Review）发现的修复

1. `fs.write` 写到了父目录（ensure_parent 返回值误用）→ 修复
2. `fs.list` 默认路径 `.` 被 normalize_rel 拒绝 → 修复
3. RUNNING→QUEUED（限流回队列）不在迁移表 → 补充为合法迁移
4. tool.call / invocation.finished 事件缺 run_id 导致 run 维度查询漏事件 → 修复
5. asyncio.CancelledError 未处理会留下 RUNNING 残留 → 落 CANCELLED 后上抛

## 已知限制（诚实声明）

- 无真实 Provider（v0.3）；无 streaming。
- 编排层（DAG/门/回炉）未实现——本版只有内核。
- SQLite 写锁为进程内 threading.Lock；多进程写同一 project.db 未支持（v0.2 单运行锁语义约束）。
- fs 写入对 NTFS ADS 语法（`file:stream`）未显式拒绝（留在工作区内，无逃逸），外审后决定是否收紧。
- Windows Job Object 未用（v0.2）；当前 python.run 用 taskkill /T。

外审驱动的关键强化（超出原始实现的部分）：
- SUCCEEDED 双重强制（迁移表 + commit 专用事务）、QUEUED→RUNNING 仅 CAS；
- 租约 owner_token 贯穿全部仓储 API，活跃态统一 fail-closed（NULL/空串=损坏）；
- 通用 transition_task 活跃态白名单（仅 RUNNING<->WAITING_TOOL），收口语义集中于 6 个专用函数；
- 状态迁移与事件同事务（transactional outbox）；
- artifact 单次读入 + 内容寻址封存（.mmagent/artifacts，经 PathPolicy）；
- kind=json 无 schema 也必须合法 JSON；
- request_cancel 状态白名单语义（无执行者直接 CANCELLED；有执行者必须 token）；
- 词法 reparse walk（resolve 之前）、ADS/保留名/尾点/首尾空白拒绝、host_code 能力位、
  python.run 最小环境白名单。
