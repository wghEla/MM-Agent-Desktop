# P1-1 — S5 calculation repair/escalation does not preserve Frozen Truth

**OPEN**

Both normal S5 calculation repair and fuse escalation ultimately dispatch the Modeler
directly. They do not mechanically execute the complete calculation-change protocol:

```
model/solver change
→ trusted Runtime executes solver
→ independent red-team recomputation
→ arbitration/G2
→ version/change manifest
→ downstream invalidation
→ regenerate dependent figures
→ synchronize dependent text
```

The S2 implementation already contains most of the solver/red-team/G2 primitives, but S5
does not invoke a cross-stage cascade.

This is more than a fidelity cosmetic gap: a late S5 calculation modification can create a
new numerical truth while figures/text/publication carriers still describe the previous one.

### Required resolution

Either:

1. implement a real S5 calc cascade with the full frozen-truth protocol and durable
   downstream invalidation, **or**
2. fail closed on late calc repair and route it to an explicitly disclosed degraded state.

Do not allow a direct Modeler receipt by itself to certify a calculation repair.

# P1-2 — G5 figure repair does not synchronize dependent text

**OPEN**

Current G5 figure repair is approximately:

```
Plotter edits script
→ Runtime reruns figure
→ repair receipt
→ current-PDF reviewer
```

The pinned R49 semantics require:

```
Plotter
→ regenerate figure
→ Writer synchronizes dependent text/captions/numeric references
→ compile
→ review
```

A changed figure can therefore diverge from its textual explanation even though the figure
itself was regenerated.

### Required resolution

Treat a figure issue as one repair transaction:

1. Plotter writes/updates script with a required model receipt.
2. Runtime executes the script.
3. Writer performs a narrowly-scoped dependent-text synchronization behind guards.
4. Only after both legs succeed does Runtime create/accept the Issue Ledger repair receipt.
5. Compile and reviewer verdict follow.

Do not let the Plotter receipt alone move the Issue to `待复核`.

# P1-3 — Guard algorithms exist but are not enforced on all late writer paths

**OPEN**

`change_guard()` exists, but Round-3 source search found no production pipeline call.

`structure_guard()` is currently enforced through `guarded_text_repair()` only on part of
the repair surface. S5 normal text rework, S5b text beauty repair, S6 text terminal repair,
and relevant S4 late revisions still have direct Writer paths.

Therefore:

- B8 Change Guard cannot be MATCH.
- B9 Structure Guard cannot yet be MATCH.

A late Writer leg can still perform a broad rewrite or structural deletion outside the one
guarded G5 path.

### Required resolution

Use one shared guarded-writer primitive for every late-stage mutation of existing paper
content. It should provide:

```
durable pre-repair snapshot
→ Writer leg
→ required receipt
→ Change Guard (0.45 normal / 0.70 escalated as applicable)
→ Structure Guard
→ whole-paper rollback on violation
→ invalidate receipt on rollback
```

Initial paper drafting need not be compared against an empty baseline; this requirement is
for revisions of an existing paper.

# Round-3 defects source-patched by reviewer

The following defects were found and patched directly in the branch. All are
**REGRESSION PENDING**.

## R3-F1 — S5 escalation receipt identity had regressed

Before patch:
- escalation used random UUID receipt ids;
- replay could increment attempts again;
- invalid/empty receipt could synthesize a fake "升格重做完成" receipt;
- failed escalation was treated as an exhausted escalation eligible for degraded release.

Reviewer fixes:
- strict non-empty model receipt artifact;
- deterministic runtime receipt id;
- no synthetic success receipt;
- failed escalation never authorizes degradation;
- missed reviewer verdict after escalation never authorizes degradation.

## R3-F2 — Final-round escalation extension was not actually executed

The code emitted `checkpoint.s5_escalation_extension` but used a fixed
`range(..., max_rounds + 1)`, so no extra reviewer round existed.

Reviewer patch:
- exactly one recoverable extension round after a **successful accepted** escalation
  started in the last normal round;
- extension round cannot start a fresh escalation;
- extension event participates in resume semantics.

## R3-F3 — G5 calculation path self-authorized degraded release

G5 was creating a new degraded approval merely because publication-time recalculation was
undesirable.

Reviewer patch:
- G5 can only consume an exact `(issue_id, generation)` approval produced earlier;
- without prior approval the calculation blocker stays active and G5 fails closed.

## R3-F4 — G5 repair receipt routing was too permissive

Reviewer patches:
- per-figure-Issue deterministic node/artifact identity;
- strict model receipt schema;
- Runtime filters to assigned Issue ids;
- deterministic generation-bound receipt ids;
- text-route receipts similarly restricted;
- G5 reviewer verdict must explicitly carry generation; Runtime no longer guesses it.

## R3-F5 — "Current PDF" reviews were not actually visual

G5/S6 prompts claimed the reviewer inspected the current PDF, but no `image_paths` were
attached. `fs.read` cannot inspect PDF pixels.

Reviewer patches:
- G5 final review renders the current PDF and reviews all page batches (max 8 images/leg);
- G5 rework review receives freshly rendered representative page images;
- S6 terminal review re-renders the final revision and reviews every page batch;
- failure to render visual evidence fails closed.

## R3-F6 — OpenAI-compatible providers had no UI-accessible vision capability

The compatible adapter defaulted to `image_input=False`, and Provider Settings could not
override it.

Reviewer patches:
- backend supports `extra.image_input`;
- desktop Provider Settings exposes "supports image input" only for
  `openai_compatible`.

Default remains false.

## R3-F7 — B14 invalidation was not durable across crash/restart

The implementation removed downstream checkpoints only from an in-memory dictionary and
wrote an invalidation event. Resume rebuilt state only from `checkpoint.s2_question`, so
the older downstream checkpoint could resurrect after a crash.

Reviewer patch:
- S2 now replays checkpoint and invalidation events in event-id order;
- invalidation acts as an append-only tombstone;
- a crash-boundary test was added.

## R3-F8 — Compile repair nodes collided across stages

`编译修复1/2` were run-global node keys reused by S4/S5b/G5. A successful/failed node in
one stage could conflict with another stage.

Reviewer patch:
- stage-scoped node keys and receipt names;
- compile repair now uses guarded repair rather than an unguarded Writer mutation.

## R3-F9 — Guard rollback was not crash-safe

The pre-repair snapshot existed only in memory. A crash after the role task sealed success
but before the outer guard ran could lose the original baseline.

Reviewer patch:
- durable guard snapshot under `.mmagent/guard_snapshots/`;
- resume reuses the original baseline;
- failed/reverted legs restore pre-repair TeX;
- rejected receipts are deleted so a later retry cannot reuse stale evidence;
- content-based code-chapter detection is now actually wired into Structure Guard.
