## Final source findings after the verified baseline

### F1 — S6 final figure repair needed dependent-text synchronization

Severity before fix: **P1 release-integrity gap**

The S6 final-page review could route a figure defect through:

```
Plotter
→ Runtime rerun plot
→ final compile
```

without the dependent-text synchronization already required in S5/G5 figure transactions.

Because S6 is the final mutable stage, a figure/caption/reference mismatch introduced here
would occur after G5 and immediately before harvest.

Source fix:

```
Plotter
→ trusted Runtime plot execution
→ guarded Writer synchronization of dependent captions/text/numeric references
→ final compile
→ mechanical publication gate
→ fresh visual terminal review
→ harvest
```

Writer-sync failure now blocks delivery.

Behavior tests are added but need one final local regression.

### F2 — degraded/unresolved state was delivered only as an opaque copied carrier

Severity before fix: **P2 / fidelity-delivery disclosure gap**

The Runtime already produced exact typed degraded-release entries and copied the complete
`交接/` carrier into delivery, but the master plan explicitly calls for known unresolved
items as a final output. There was no human-readable Runtime-owned delivery report.

Source fix:

- Runtime generates `交付/交付报告.md`;
- exact degraded questions and review `(id,generation)` entries are listed mechanically;
- non-resolved review-ledger entries are listed;
- run metrics are listed;
- the model is not responsible for deciding what unresolved state to disclose.

This corrects the stale A12 matrix claim that the review-level runtime producer was missing.
A12 may be promoted only after the new delivery-report test is locally green.

# Real-provider readiness assessment

The provider layer is ready for a real smoke after package validation:

- credentials are referenced through the credential-store boundary;
- OpenAI-compatible image input is explicit opt-in;
- OpenAI-compatible `reasoning_effort` is explicit opt-in and omitted by default;
- compatible 4xx bodies redact the API key;
- OpenAI-style image content is actually serialized as base64 `image_url` parts;
- five provider protocol adapters have offline contract tests.

Important limitation:

`OpenAICompatibleProvider.test_connection()` currently probes `GET {base_url}/models`.
Some otherwise valid compatible relays do not expose that endpoint. A failed Settings-page
connection probe therefore does not necessarily prove chat-completions is unusable. The
real smoke should validate an actual minimal generation request, not rely exclusively on
`/models`.

This is not currently a release P1 because the actual generate path is independent, but it
is a usability caveat for the final manual smoke.
