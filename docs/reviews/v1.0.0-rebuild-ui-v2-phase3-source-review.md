## Scope implemented

### Provider catalog

Runtime-backed catalog now supplies presentation metadata for:

- OpenAI;
- Anthropic;
- Gemini;
- Groq;
- DeepSeek;
- ZCode;
- OpenAI Compatible.

Presets remain UI conveniences.  The Runtime adapters remain the existing protocol set.

ZCode intentionally has no guessed/private Base URL in source; the user supplies the
endpoint and exact model exposed by their account.

### Model discovery

Model discovery is separate from generation.

- list request only;
- no generation fallback;
- bounded to 500 unique model IDs;
- manual Model ID entry remains available;
- Compatible models endpoint is configurable;
- Compatible models discovery can be explicitly disabled.

Saved-profile discovery retrieves the credential through CredentialStore.  A missing or
unreadable saved credential is surfaced explicitly rather than silently behaving as a
keyless profile.

### Connection validation

Saved Provider Test Connection validates the configured model where a model-list endpoint
is available.

New-provider setup additionally has an ephemeral `POST /providers/test-config` preflight:

- transient API key only;
- no provider/model-profile row created;
- no Credential Manager write;
- provider is always closed after the test.

Unlike Discover Models, Test Connection may use an existing adapter's documented minimal
generation fallback when the model-list endpoint is absent/unsupported.

### Provider lifecycle

Provider Settings now supports:

- create;
- select;
- edit;
- delete;
- model-list refresh;
- API Key replace;
- API Key clear;
- capability summary;
- capability-driven Advanced fields.

A newly-created profile becomes the selected profile.

### Secret and endpoint boundary

Persisted profiles, transient model discovery and ephemeral Test Connection share common
validation:

- Base URL must be absolute HTTP(S);
- no Base URL username/password;
- no query or fragment parameters in Base URL;
- secret-bearing custom header names are rejected;
- custom headers must be strings;
- Compatible models/completions endpoints must be relative paths;
- absolute/protocol-relative/query/fragment/backslash endpoint-path escapes are rejected.

Discovery error details redact both the API key and supplied custom-header values.

### Credential-to-endpoint binding

A saved credential is scoped to the Provider's current protocol + Base URL.

While a credential exists:

- changing protocol is rejected;
- changing Base URL is rejected.

The UI locks those two fields and explains that the key must be cleared first.

This prevents an existing Windows Credential Manager secret from silently following a
profile to a different endpoint.

### Compatible auth binding

The Runtime API now enforces, independently of the UI:

- `auth_style=none` means explicit keyless/no-auth;
- a transient or persisted credential cannot coexist with `auth_style=none`;
- API-key mode uses Bearer or x-api-key;
- adding a Key to a previously keyless Compatible profile requires choosing the auth style.

This closes the contradictory state "API Key saved but never transmitted".

### Credential deletion semantics

Credential cleanup is secret-first:

1. delete Credential Manager secret;
2. then remove/clear the SQLite reference.

Windows Credential Manager deletion now ignores only ERROR_NOT_FOUND (1168).
Other deletion errors raise `CredentialDeleteError` and stop the operation before SQLite
forgets the credential reference.

This favors an explicit fail-closed missing-credential state over an unreferenced orphaned
secret.

### OAuth extension contract

A typed OAuth adapter registry exists for future documented third-party desktop flows.

Current behavior is deliberately fail-closed:

- no OAuth adapter is registered;
- no Provider preset currently advertises an operational OAuth flow;
- Catalog removes OAuth unless both metadata and a Runtime adapter exist;
- OAuth credential result keeps the credential out of repr;
- no browser Cookie import;
- no consumer session-token extraction;
- no borrowed Codex/Claude Code/other first-party OAuth client.

Therefore **account login is not currently a product feature**.

## Source-review findings fixed before local handoff

1. Transient model discovery originally had weaker URL/header validation than persisted
   Provider profiles.  It now shares the same validation boundary.

2. Model-discovery errors could expose custom-header values echoed by a provider.  These
   values are now included in the redaction set.

3. Compatible models/completions paths could be used with unsafe absolute/secret-bearing
   forms.  They are now normalized/validated as same-host relative paths.

4. API-key mode could coexist with `auth_style=none`.  UI and Runtime now reject this
   contradictory state.

5. A saved API key could survive an edit to a different Base URL/protocol and then be sent
   to the new endpoint.  Credential-to-endpoint binding now forbids this.

6. Credential clear/delete removed SQLite references before deleting the system secret.
   Cleanup order is reversed.

7. Windows CredentialStore.delete swallowed every OS failure.  Only NOT_FOUND remains
   idempotent; other failures are explicit.

8. Compatible `models_path=None` (discovery disabled) was lost when entering Edit and
   could be silently restored to `/models`.  The edit form now preserves explicit disable.

9. New-provider setup required saving a credential/profile before Test Connection.
   Ephemeral pre-save Test Connection now exists and has a distinguishing no-persistence
   integration test.

10. Draft Test Connection results could remain visually stale after draft fields changed.
    The result now invalidates when request-relevant form state changes.
