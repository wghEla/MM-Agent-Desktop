## Implemented Phase-2 scope

### 1. Workspace tree

New authenticated sidecar endpoints:

- `GET /projects/{project_id}/workspace/tree`
- `POST /projects/{project_id}/workspace/read`

The tree is not a direct frontend filesystem scan.

Runtime-side controls:

- fixed user-visible root allowlist;
- excludes `.mmagent`;
- `PathPolicy` revalidation for every existing returned path;
- bounded depth;
- bounded item count;
- read-only preview;
- same authenticated sidecar boundary as existing artifact APIs.

Frontend:

- left-rail collapsible file tree;
- root/folder collapse;
- type hints for text/image/PDF/binary;
- selected file opens in the existing right Artifact preview;
- automatic refresh after import and periodically during RUNNING runs.

### 2. First-run onboarding

The no-workspace surface now presents the actual product sequence:

1. 工作区
2. 模型
3. 材料

Primary actions:

- 新建工作区
- 打开已有工作区
- recent workspace reopen

After a workspace is created/opened, the center surface continues the same setup sequence:
workspace is marked complete, Provider status is projected from the real provider list, and
the material step points back to the import/file-tree surface. It does not claim materials
are valid or complete; Runtime Gates remain authoritative.

This is presentation/workflow guidance only; it does not create a second run/pipeline state.

### 3. Create/open workspace dialogs

Dedicated workspace dialogs replace the permanent path-heavy project form.

Create:

- native folder picker;
- derived project name;
- quality profile;
- advanced manual path fallback.

Open:

- native folder picker;
- existing-workspace wording;
- no auto-resume semantics.

Backend errors remain visible in the dialog instead of closing silently.

### 4. Recent workspace hardening

Recent entries remain presentation-only localStorage bookmarks.

New behavior:

- remove-from-recent action;
- removal never deletes or mutates the workspace;
- stored values are type-sanitized before rendering;
- entries sort by last-opened time.

### 5. Preview integration

Artifact dock now also reads selected workspace-tree files through the bounded
`workspace/read` endpoint.

A source-review bug was fixed where periodic artifact refresh could clear an input-file
preview because input files are not part of the output-artifact list.

### 6. Dependency reproducibility cleanup

The previously verified Tauri JS minors are pinned exactly in npm metadata because local
release validation already proved mismatched JS/Rust minor versions can make Tauri reject
the release build. The verified Rust crate versions are also pinned exactly in Cargo.toml
to keep a future cargo update from recreating the same cross-language minor drift.

## Source-review findings fixed before handoff

1. **Create/open failure feedback**
   - failure originally remained behind the dialog;
   - dialog now receives and shows the backend error and stays open.

2. **Workspace preview erased by artifact refresh**
   - output artifact polling could clear a selected input-file preview;
   - external workspace selection is now preserved and reopened across workspace refresh.

3. **Recent bookmark corruption / invisible reopen error**
   - malformed localStorage values could reach React rendering;
   - values are now sanitized and ordered before use;
   - failed recent-workspace reopen now surfaces its backend error on the Welcome view.

4. **Tree path inspection ordering**
   - workspace root/entry paths are validated through `PathPolicy` before type/existence
     inspection used for traversal;
   - directory-first sorting is performed only after validation.

5. **Dialog lifecycle while backend action is pending**
   - workspace create/open dialog cannot be dismissed by backdrop/close while the backend
     action is in flight.

6. **Live artifact polling stale-selection hazard**
   - artifact-list polling no longer clears the user-selected preview, avoiding stale
     closure races during a running pipeline.
