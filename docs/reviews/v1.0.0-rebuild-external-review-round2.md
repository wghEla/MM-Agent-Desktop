## R1 P1-2 — G5 authoritative closure

### Result

**OPEN P1**

The Engine now calls `run_g5_rework()`, so the dead-code/integration issue from round 1
was partially addressed. However the rework function still is not a real Issue-Ledger
closure.

Observed source behavior:

1. Plotter and writer repair legs use `expected=[]`; no repair receipt is required.
2. Their return status is ignored.
3. No call to `IssueLedger.收回执()` exists in the G5 rework path.
4. No reviewer verdict is applied to the original blocking Issue.
5. In-memory ledger changes are not durably written back to
   `台账/审稿台账.json`.
6. Therefore an active S5 blocker cannot actually become `已消解` through G5 rework.
7. The previous implementation's per-round defect-hunter boolean was not part of the
   final mechanical `check_g5()` decision.

### Reviewer source patch

A source-only patch now makes the final step call `run_g5()`, which adds a **fresh final
current-PDF defect-hunter review** after the bounded rework loop.

This removes the specific false-pass path where all per-round defect reviews could reject
the paper while the final mechanical gate still returned PASS.

### Still required

G5 repair must be:

```
assigned Issue
→ runtime-owned repair receipt
→ 待复核
→ reviewer/defect verdict carrying generation
→ 已消解 / 未消解
→ durable ledger writeback
→ final mechanical + current-PDF review
```

Until that exists, A20 remains PARTIAL.

## R1 P1-3 — S5 blocking fuse escalation

### Result

**OPEN P1**

The new code is still marker-like despite executing a role leg.

Observed source behavior:

- The code still exits on
  `if converged or round_num >= max_rounds`
  **before** fuse processing. Therefore final-round fuse candidates are skipped.
- Escalation uses `expected_artifacts=[]`.
- No escalation receipt is required.
- No `IssueLedger.收回执()` transition is performed.
- The Issue remains `待改`.
- `s5.escalation_executed` is emitted unconditionally after awaiting the role leg; the
  returned status is not checked.
- A failed role leg can therefore still be recorded as "executed".
- A calculation-class escalation invokes the modeler directly without the required
  recalc → red-team → G2 → downstream invalidation cascade.

The added tests in `test_repair_lane_ordering.py` manually append/query an event; they
do not execute `run_s5()` and therefore do not prove the real escalation control flow.

### Required

Implement a runtime-owned escalation state transition keyed by
`(issue_id, generation)`, with a required receipt, reviewer re-verdict and crash-safe
checkpoint. Calculation escalation must either execute the full calculation cascade or
be explicitly degraded after the bounded escalation is exhausted.
