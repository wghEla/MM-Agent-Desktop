P1-1 — 裁定没有绑定 round / attempt，旧裁定可以消解已经重开的新问题

这是目前最重要的 blocker。

收裁定() 只根据 id 查当前 Issue：

Python
运行
x = self._get(str(r.get("id", "")).strip())
...
x.状态 = 已消解

传入的 轮次 只写进历史记录，不参与 CAS / generation check。

因此下面的序列合法发生：

Round 1:
意-1-01 → 修复 → 待复核 → 已消解

Round 2:
同一问题再次出现
并入(... 对应="意-1-01")
→ 重开
→ 状态 = 待改
→ 重开次数 = 1

随后一个延迟/重放的 Round-1 裁定到达：
收裁定(
    [{"id": "意-1-01", "裁定": "已消解"}],
    轮次=1,
)

→ 当前 Round-2 的待改问题被直接置为 已消解

随后：

Python
运行
t.收敛()

可以返回 True。

这正好击中了 v1.0 宣称的 crash recovery / retry 场景：旧消息重放不能改变新 generation。

建议 Issue 至少增加：

Python
运行
revision: int
attempt_id: str | int
pending_review_attempt: ...

或者最低限度：

Python
运行
收裁定(..., expected_attempt=N)

并做 compare-and-transition：

只有
状态 == 待复核
且 expected_attempt == 当前 attempt
才允许裁定

旧 attempt 必须被识别为 stale，并保持当前状态不变。

P1-2 — 收裁定() 没有真正实现状态机，只是任意状态覆盖

函数注释写：

评审腿裁定：只有评审能置已消解。

但是实际没有任何 transition guard。

现在以下全部允许：

待改 → 已消解
搁置 → 已消解
已消解 → 未消解
未消解 → 已消解
待改 → 未消解

甚至根本没经过：

待改
→ 收回执
→ 待复核
→ reviewer 裁定

就可以直接：

Python
运行
t.收裁定([{"id": "...", "裁定": "已消解"}])

如果 IssueLedger 被定义成“状态机”，核心对象自身应该守住 transition invariant，不能依赖调用者“应该按顺序调用”。

我建议至少收死为：

待改 --receipt--> 待复核
未消解 --receipt--> 待复核

待复核 --review unresolved--> 未消解
待复核 --review resolved--> 已消解

至于 搁置 是否允许重开，应定义一个专用 primitive，而不是被普通 收裁定() 改掉。

P1-3 — "已消解" 使用 startswith()，存在直接的 fail-open 解析

现在：

Python
运行
if 裁.startswith("已消解") or 裁.startswith("已解决"):
    x.状态 = 已消解

所以以下都会判定为 resolved：

"已消解：否"
"已消解不了，问题仍存在"
"已解决？没有，数值仍然错误"

对于 LLM reviewer 输出，这是现实可达输入，不是纯理论情况。

Gate / Ledger 的终态不能用自由文本前缀推断。

应该让 reviewer 返回结构化 enum，例如：

JSON
{
  "id": "意-1-01",
  "裁定": "RESOLVED"
}

只接受精确集合：

Python
运行
Literal["已消解", "未消解"]

未知值应 reject / 未消解，绝不能猜测成 resolved。

这是典型的 fail-closed 要求。

P1-4 — receipt 不幂等，crash/retry 会虚增“尝试次数”，提前触发熔断

现在每收到一次回执都会：

Python
运行

没有 receipt_id / attempt_id 去重。

所以：

随后 reviewer 只判一次：

Python

马上：

Python

于是 一次真实修改可以被当成“两次修改仍失败”。

如果 S5 后续把熔断候选搁置，这会进一步变成：

→ attempts 虚增
→ premature fuse
→ 搁置 blocker

→ 假收敛

这和你 v1.0 特别声明的 crash recovery / retry 是直接冲突。

需要：

attempt_id / receipt_id 唯一
同一 receipt replay = no-op

而不是再次计数。
