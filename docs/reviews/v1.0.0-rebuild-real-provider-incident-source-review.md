## Source findings and fixes

### RP-F1 — Retry-After was parsed and persisted but never awaited

Severity: **P1 real-provider resilience defect**

Before fix:

- provider adapter parsed `Retry-After`;
- `AgentLoop` emitted `task.rate_limited {retry_after_s}`;
- `run_status_wave` reduced concurrency;
- retry pass started immediately.

This contradicted `RateLimitError`'s own contract ("按 retry_after 重试") and could
amplify rate limiting on constrained relays.

Fix:

- each wave pass records its start event id;
- before a retry pass, the wave reads `task.rate_limited` events created during that pass;
- the largest finite positive `retry_after_s` is honored;
- `wave.retry_backoff` is durably recorded;
- the wait is cancellation-aware and thread-free;
- concurrency reduction + one-retry semantics remain unchanged.

Distinguishing test:
`test_direct_role_leg_429_honors_retry_after_before_retry`.

### RP-F2 — Reader could seal a contract guaranteed to fail G0

Severity: **P1 cost/correctness-boundary inefficiency**

Before fix, `ProblemContract` allowed `问题=[]`.  The Reader therefore sealed SUCCEEDED,
S0.3 spent another real model call, and only G0 rejected the empty problem list.

Fix:

`ProblemContract` now rejects producer artifacts already guaranteed to fail G0:

- empty `问题`;
- blank per-question `原文摘录`;
- blank per-question `解读`;
- empty per-question `需求条目`;
- ambiguity entries with blank `裁定` or blank `理由`.

This moves deterministic producer validation earlier without weakening G0.  A failed Reader
leg still receives the existing one retry, giving the model a chance to repair the carrier
before S0.3 spends tokens.

Distinguishing extension:
`test_s0_reader_enforces_canonical_contracts_before_g0`.

### RP-F3 — max-turn exhaustion depended on a closing prose turn

Severity: **P1 agent-loop completion defect**

Before fix, if turn 16 contained tool calls, the loop failed immediately with "超过最大轮数"
without checking whether all required artifacts had already been written and validated.

That conflicts with the core invariant that Runtime artifacts, not model self-declaration,
determine success.

Fix:

- no change to the 16-turn default;
- at the turn limit, a task with required artifacts performs one final Runtime artifact
  verification;
- valid required artifacts may seal SUCCEEDED even without a closing prose sentence;
- incomplete/invalid artifacts still fail closed;
- tasks with no required artifact still require normal termination;
- `agent.max_turns_artifact_check` and
  `agent.max_turns_artifacts_accepted` provide audit evidence.

Distinguishing tests:

- `test_max_turns_accepts_valid_required_artifact_without_closing_text`;
- `test_max_turns_still_fails_when_required_artifact_is_missing`.

### RP-F4 — Reader was instructed to inspect directories but had no fs.list

Severity: **P1 real-provider efficiency / satisfiability defect**

Reader must inspect `输入/题目/` and `输入/数据/`, but its allowed tools were only
`fs.read` / `fs.write`.  A real model that did not know filenames had to guess names or
try to read directories, producing extra tool turns and permission/tool errors — especially
harmful on RPM-limited providers.

Fix:

- only Reader gains `fs.list`;
- its read scope remains `输入/**`;
- Reader system prompt explicitly says: list the two input directories first, then read
  actual file paths;
- no other role receives broader filesystem authority.

Distinguishing test:
`test_reader_can_enumerate_input_directories_before_reading`.

### RP-F5 — invocation reasoning metadata could disagree with wire behavior

Severity: **P2 diagnostics / capability-contract defect**

For a compatible provider with `reasoning_effort=false`, the actual HTTP adapter omitted
reasoning, but `ModelBoundProvider` could still record the role default `xhigh` as the
effective invocation reasoning.  This made incident diagnosis misleading.

The same path could also pass `xhigh` to a protocol whose own capability declaration only
advertised `low/medium/high`.

Fix:

- `BaseProvider.resolve_reasoning` now normalizes requested reasoning to declared
  capabilities;
- unsupported reasoning → `None`;
- role `xhigh` → `high` when the protocol's highest declared tier is high;
- `ModelBoundProvider` sends configured/default reasoning through the inner provider's
  resolver;
- stored effective reasoning now matches the capability-normalized wire behavior.

Distinguishing test:
`test_effective_reasoning_is_normalized_to_declared_provider_capabilities`.
