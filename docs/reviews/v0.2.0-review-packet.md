## 3. Architecture

ProcessManager → Job Object per spawn（KILL_ON_JOB_CLOSE：Runtime 崩溃时工具进程一并死亡，
复现上游 setsid 进程组 + 防孤儿腿意图的 Windows 等价物）。
Registry 同名重派 → 旧进程先回收（上游 R60）。
EnvironmentManager 输出 EnvironmentReport（hard_failures=不得开炉；warnings=降级提示）。
RoleSpec.permissions(**vars) → RolePermissions（v0.1 权限系统），模板变量已校验。

## 4. Public interfaces

```python
ProcessManager.spawn(name, argv, cwd, env) / communicate(proc, timeout_s, cancel)
             .kill(name) / .recycle(name) / .registry.orphans() / .shutdown()
EnvironmentManager: probe_all(workspace_root) -> EnvironmentReport
             discover_xelatex / discover_matlab / discover_ghostscript / managed_python
roles: get_role(id).permissions(**vars) -> RolePermissions; all_roles(); role_ids()
```

## 5. State transitions

无新状态机（v0.1 的 11 态不变）。新增进程生命周期：spawn→(communicate|timeout→kill|cancel→kill)→recycle。

## 6. Security boundary

- Job Object：KILL_ON_JOB_CLOSE——即使 Runtime OOM/崩溃，工具进程树随 Job 句柄关闭而终止；
- python.run 保持 host_code=True 能力门（v0.1 P0-3 语义），最小环境白名单不变；
- 角色注册表是权限**配置**事实：红队 read_scopes 不含 求解/**、建模笔记、解读；
  无 host_code；测试断言端到端 PermissionDenied；
- 环境发现只读（执行 --version / -help 级验证），不修改用户安装。

v0.1 的全部故障注入保持回归。

## 9. Known limitations（诚实声明）

1. Job Object 失败时（OpenProcess 权限异常）回退 taskkill /T——成功概率极低但存在；
   回退路径同样记录。
2. communicate() 阻塞读 PIPE：进程输出超大时依赖 OS 管道缓冲（communicate 全量读取，
   无死锁，但内存占用与输出成正比；工具输出已在 loop 截断回填，风险可控）。
3. 取消约定码 rc=-99 是本 Runtime 内部约定（真实 OS 不产生 -99 退出码）。
4. 环境发现的 --version 执行有 30s 超时；恶意 PATH 劫持场景不在威胁模型内
   （单用户桌面，威胁模型明确为：抵御模型产物越权，不抵御本机管理员）。
5. 角色注册表暂无 prompt.md（v0.4+ 按版本落地）；本版只承诺权限/路由事实。

## 11. Focused questions

1. KILL_ON_JOB_CLOSE 在 Runtime 崩溃（非正常退出）时是否可靠？句柄继承
   （子进程再派生时句柄是否泄漏到孙进程之外）是否需要 HANDLE_FLAG_INHERIT=False？
2. communicate 全量读 PIPE 的内存上限是否应改为滚尾（只留尾部 N 字节）？
3. rc=-99 约定与 Job Object 终止码 0 的区分是否足够稳健？
4. 环境发现深度搜索 `**` 在超大 texlive 根下的性能与符号链接循环风险？
5. 角色注册表作为权限配置事实，是否需要 schema 校验（防 typo 导致 scope 意外放宽）？
