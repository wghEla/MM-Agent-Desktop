  tool through `ProcessManager` (Job Object, KILL_ON_JOB_CLOSE), managed
  `runtime\python.exe` 3.11.16.

## Defects found and fixed during this gate (source fixes → repackage)

1. `WindowsCredentialStore` was unusable on current pywin32: `CredWrite`
   requires a Unicode `CredentialBlob` (bytes → TypeError), and `CredRead`
   returns the blob as UTF-16LE bytes. Fixed write(str)/read(utf-16le|utf-8);
   3 focused tests (`tests/unit/test_credentials.py`). Any user entering an API
   key in the installed product had hit this.
2. Keyless provider profiles (local relays — a supported desktop use case) sent
   an empty `Authorization: Bearer ` header, which httpx rejects
   (`Illegal header value`), making every chat call fail at network level.
   `openai_chat` / `openai_responses` now omit the header when no key is
   configured (`openai_compatible` already did); 2 focused tests.
3. Both fixes touch the frozen sidecar → full repackage per gate rule:
   PyInstaller sidecar + Tauri release + NSIS rebuilt, silent reinstall,
   startup smoke exit 0, and the gate ran on the NEW install.
4. Post-gate residual (deferred to Real Provider Gate): the frozen sidecar's
   credential READ path returned "credential not found" for an entry that
   Credential Manager demonstrably contains (verified via `CredEnumerate`).
   Write path is proven live in-product (provider creation with key succeeded);
   the read round-trip is proven by unit tests in the dev tree. To be
   re-verified end-to-end with a real credential.
