## 6. State transitions

TaskStatus 11 态；迁移表白名单见 `state/models.py::_TASK_TRANSITIONS`。
关键不变量：**SUCCEEDED 是终态**；只能经 `commit_task_success()`（与 artifacts 同事务）进入；
FAILED→READY 可重试；RUNNING→QUEUED 供限流回队列；CANCELLED→READY 显式重跑。
每次迁移写 event（`task.status`，含 from/to）。

## 7. Security boundary

- 路径：normalize_rel 拒 `..`、`.`分量、绝对路径、盘符、NUL；resolve 后 must be inside root；
  Windows lstat 检查路径组件 reparse point（junction/symlink 逃逸）→ PathEscape。
- 权限：角色 read_scopes/write_scopes（`**` 跨段 glob、`{question}` 变量模板）+ allowed_tools；
  registry.invoke 第一道检查工具白名单，工具内部第二道检查路径 scope。
- 红队隔离（测试）：red_team 角色读 `求解/问题1/求解_问题1.py` → PermissionDenied（权限层非提示词）。
- 密钥：providers 表仅 api_key_ref 字段；本版无任何网络调用。
- events 表触发器拒绝 UPDATE/DELETE（append-only 物理强制）。

## 10. Known limitations（诚实声明）

1. 无真实 Provider / streaming（v0.3）；Provider 层只有接口 + mock。
2. 编排（DAG/门/回炉/checkpoint）未实现。
3. SQLite 并发：进程内 threading.Lock 串行化；多进程写未支持（靠单运行锁约束）。
4. `transaction()` 不支持嵌套（当前无嵌套调用，无保护）。
5. python.run 继承完整 os.environ；未做 env 白名单。
6. fs 写未拒绝 NTFS ADS 语法（`file:stream`）——留在工作区内、无逃逸，但可绕过扩展名检查
   （`python.run` 只认 `.py` 结尾，ADS 后缀 `x.py:hidden` 以 `:hidden` 结尾会被拒；`x.py:s` 这类以合法流名结尾的会被 `.py` 判定通过吗——`str(path).endswith('.py')` 对 `x.py:s` 为 False，已拒）。
7. cancellation.wait() 用线程阻塞包装，长期挂起场景占一个线程。

## 12. Focused questions

1. path_policy 的 reparse 检查只沿 parent 链向上走到 root：是否有 Windows 下的绕过
   （如符号化 reparse 在 leaf 文件本身、或 TOCTOU 窗口）？
2. SQLite 单写者 + threading.Lock：在"一个项目一个 driver 进程"约束下是否足够？
   WAL + FULL sync 的崩溃一致性是否有坑？
3. Agent Loop 的取消路径（TaskCancelled / asyncio.CancelledError 双处理）是否有竞态
   （如工具刚返回、取消刚触发时的状态迁移冲突）？
4. fs 权限的 glob 语义（`**`、`{question}` 模板替换）是否有绕过面（大小写、尾点、UTF-8 变体）？
5. 限流回队列 RUNNING→QUEUED 是否引入重入风险（同任务并发两个 loop 实例）？
   目前无 run 级任务租约。
